## 4. Companies

### v1 (`api.nfe.io/v1/companies`) — **PROVADO**
- Envelope de lista: `{"companies":[…], "page": <int>}` — `page` é **inteiro** (eco do `pageIndex`);
  **não há** `totalResults`/`totalPages`. Fim da paginação = página com menos itens que `pageCount`.
- `pageIndex`: 1-based; `0` → 400 `"pageIndex must be greater or equal to 1"`.
- `pageCount`: aceita 2–50; `1` → 400 `"pageCount must be between 1 and 50"` (mensagem mente);
  `51`/`100` → 400; omitido → 10 itens.
- Retrieve por id **ou** CNPJ (`/v1/companies/<CNPJ_TESTE>`) → 200 `{"companies": {…}}` — objeto
  único sob chave **plural**.
- Id inexistente → 404 `{"errors":[{"code":40401,"message":"company id not found"}]}`.
- Itens trazem `certificate {thumbprint, modifiedOn, expiresOn, status}`.

### v2 (`api.nfse.io/v2/companies`) — **PROVADO**
- Envelope `{"hasMore": bool, "companies": […]}` (spec não declara `hasMore`). Retrieve → `{"company": {…}}`.
- `limit`: 1–50; `51` → 400 `"limit must be less than 50"` (mensagem mente, 50 é aceito);
  `0` → 200 com lista vazia **e `hasMore: true`**; omitido → 10.
- Cursor `startingAfter`/`endingBefore` funciona nos dois sentidos.
- **Varredura completa terminou sem erro:** 662 empresas, sem duplicatas. O "registro venenoso"
  (`startingAfter=3450bc62…`) que derrubava o gate em 2026-07 **hoje responde 200**.
- **Paridade v1×v2:** v1 = 357 empresas, v2 = 662; v1 ⊂ v2 (0 só em v1). v1 lista só empresas
  com inscrição municipal (escopo NFS-e).
- **Projeções divergem (continua):** v1 tem `certificate, environment, federalTaxDetermination,
  fiscalStatus, issRate, lastRpsSent, legalNature, municipalTaxDetermination, rpsNumber,
  rpsSerialNumber, specialTaxRegime`; v2 tem `accountId, municipalTaxes, stateTaxes`.
  Na empresa de teste, `municipalTaxNumber` é `""` no v1 e, no v2, **contém o id (32-hex) da
  inscrição municipal** — mesmo nome, semântica diferente.
- Dados NFS-e (ambiente, RPS, ISS) vivem em `GET /v2/companies/{id}/municipaltaxes` →
  `{"hasMore", "municipalTaxes":[{id, companyId, accountId, status, city, taxNumber,
  specialTaxRegime, rpsSerialNumber, rpsNumber, issRate, environment, fiscalStatus, …}]}`.

**Leitura para o gate v1→v2:** critério 1 (varredura quebra com 500) **não reproduz mais**;
critério 2 (projeções/`municipalTaxNumber` divergentes) **continua**. Ver `DECISOES-PENDENTES.md` (D3).

## 6. NFS-e (`api.nfe.io/v1/companies/{id}/serviceinvoices`) — **PROVADO**

- Lista: `{"serviceInvoices":[…], "page": <int>}`. `pageIndex=0` → 400
  `"page index must be greater then zero"` (mensagem diferente da de companies). `pageCount` aceita
  **1**–50 aqui (51/100 → 400). Filtros `issuedBegin/issuedEnd` e `hasTotals` aceitos (200), mas
  **`hasTotals=true` não acrescenta totais**: o envelope continua `{serviceInvoices, page}` (a spec
  promete `totalResults`/`totalPages`).
- Amostra de 50 notas: `flowStatus` ∈ {`Issued`, `Cancelled`}; `status` idêntico ao `flowStatus`
  nessas amostras. União de chaves: 43 campos (lista no JSON cru; inclui `paidAmount`,
  `paymentMethod`, `nbsCode`, `approximateTotals`, `rpsStatus`).
- Retrieve → 200 objeto nu (sem envelope).
- `GET …/external/{externalId}`:
  - existente → 200 `{"serviceInvoices":[{…}], "page":1}` (**lista**, a spec diz objeto);
  - inexistente → **200 `{"serviceInvoices":[], "page":1}`** (não 404).
- Id inexistente ou malformado → 404 string `"service invoice with id (…) was not found"`.
- Empresa inexistente (24 ou 32 hex) → **404 `"Company not found."`** (o vault registrava 503 —
  mudou, ao menos no GET; para POST continua **INFERÊNCIA** = 503, fonte `PHP/Retry seguro e idempotência.md`).
- `GET …/{id}/status` → **400** ProblemDetails `errors.rpsNumber: "The value 'status' is not valid."`
  em 2 amostras. **Não existe rota de status em GET**: o polling tem que usar `GET …/{id}`.
- Downloads:
  - `GET …/{id}/pdf` e `…/xml` → **302** para `https://api.nfse.io/v1/blob/download?<b,e,s>`
    (URL pré-assinada), independente do `Accept`. Seguido **sem credencial** → 200
    `application/pdf` (`%PDF-1.4`, ~55 KB) / `application/xml` (~1,3 KB).
  - XML começa em `<Nfse><InfNfse>` **sem** prólogo `<?xml` (2 amostras).
  - `…/{id}/pdf` de nota inexistente → 404 ProblemDetails.
  - `…/{id}/cancellation-xml` de nota cancelada (provedor legado) → 404 string explicativa
    (`"…National environment only…"`).
- **Implicação de segurança:** o redirect muda de host (`api.nfe.io` → `api.nfse.io`); a URL é
  autoportante. O SDK deve seguir o redirect **sem** reenviar a chave.
- **INFERÊNCIA (escrita, não sondado hoje):** `POST` → 202 + `Location` com esquema `http://`
  (fixture `service-invoice-rtc-create.json`); `DELETE` (cancelar) → 202 + `Location`;
  `externalId` duplicado → 400 `"service invoice with external id (…) already exists"`;
  `Idempotency-Key` ignorado; 500/504 com nota criada (fontes: `PHP/Retry seguro e idempotência.md`,
  `PHP/Incidente 504 e duplicidade em produção.md`).

## 9. Consultas de dados — **PROVADO**

- **CNPJ** (`legalentity.api.nfe.io`, chave de dados): `v1`, `v2` e **`v3`** de `basicInfo` respondem
  200, com **tipos diferentes para `federalTaxNumber`**: v1 = string formatada `"00.000.000/0001-91"`
